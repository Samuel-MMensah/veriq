# Session 2026-10-26-02: Prompt 10, Real staff sign-in, the admin side, and a top-notch patient side

## Summary
Staff now sign in with an email and a password. Veriq and Supabase send no email or SMS:
- An admin makes each account in the app and hands over a one-time password.
- The person sets their own password at first sign-in.

A full admin side works at 390 px and on a laptop:
- An overview with to-do counts.
- Staff accounts.
- Hospital verification, with who and when.
- Held-report review.
- An append-only admin log.
- "Needs a location" with search and a map preview.

Only a verified hospital's staff can publish, and they can now set an "open till" time (rule F). The patient screens share one set of design tokens and components.

2. Sign in as admin@veriq.test / local-admin-pass. You should see three to-do counts, each with "Counted at …".
3. Staff accounts: make a "Hospital staff" account for Dansoman Polyclinic. Copy the one-time password from the green panel.

## Problems and risks
- **Supabase may still send email if sign-up stays on.** Anyone with the public anon key can call sign-up or "reset password" on Supabase directly. Turn off "Allow new users to sign up" (docs/DEPLOY.md). Supabase's password-reset endpoint can't be switched off; it only emails existing staff. Severity: medium.
- **The sign-in throttle is per server instance.** It slows guessing but doesn't stop it across Vercel instances. Supabase's own limits also apply. Severity: medium.
- **The demo login is on unless `DEMO_LOGIN=off`.** It can now only touch demo data, but it must be off on the real site. Severity: medium.
- **Staff emails and names are now stored in `profiles`.** This is staff data, not patient data, so rule 2 isn't affected, but it belongs in the DPC registration. Severity: low.
- **Till times around midnight.** A till time is a time of day; one entered just before midnight can't roll over to the next day. The e2e till test would fail if run between 23:58 and midnight. Severity: low.
