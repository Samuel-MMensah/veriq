## Decisions I made
- B1 compares refused with accepted only after the hospital's answer (also added to docs/DECISIONS.md)
- Windows include their boundary; a device can report again exactly 7 days later (also added to docs/DECISIONS.md)
- In S1, a status over 72 hours old sorts as unknown (also added to docs/DECISIONS.md)
- Burst: the 11th report in an hour and later are held (also added to docs/DECISIONS.md)
- Device hash is `sha256(deviceId + ":" + secret)` (also added to docs/DECISIONS.md)
- Top-up "newer" and "disagree" are defined precisely (also added to docs/DECISIONS.md)
- K counts NHIA and insurer lists, and gaps come from the search log (also added to docs/DECISIONS.md)
- Shared time helpers in `lib/rules/time.ts` (also added to docs/DECISIONS.md)

## Problems and risks
- `limits.ts` uses `node:crypto`, so it is server only. Importing it in a client component would break the build. Prompt 5 uses it from `/api/reports` only: low
- Rule A needs a server secret. Prompt 5 must add one, for example `REPORT_HASH_SECRET`, to `.env.local` and Vercel: low
- Some edge choices above are my reading of the spec. Please check the B1 one especially, because it decides when Pinecrest-style warnings clear: medium
